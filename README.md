# 喫茶 とまり木（cafe-time）

静かな行きつけのカフェで、自分の作業時間を積み重ねながら常連になっていく、ブラウザ向けの作業用放置ゲームです。

メニューを選んで「作業をはじめる」を押したら、あとは現実の作業に戻るだけ。
作業を終えて席を立つたびに、少しずつ店になじんでいき、頼めるメニューが増えたり、店内のどこかが変わったりします。

- アカウント登録なし・バックエンドなし（記録はブラウザの中に保存）
- 作業中は画面を見ている必要がありません（別タブでも、リロードしても、時間は実時間で計測）
- 現実の時刻に合わせて、朝・昼・夕方・夜と店内の光が変わります。日によって雨も降ります
- クリック連打も、期間限定の報酬も、競争もありません

## 技術構成

| 用途 | 採用したもの |
| --- | --- |
| ビルド | Vite 8 + TypeScript（strict） |
| UI | React 19（状態は自前の小さなストア + `useSyncExternalStore`） |
| 店内の描画 | Canvas 2D。低解像度で描いて CSS で拡大するドット絵（画像素材なし） |
| 音 | Web Audio API による合成（音源ファイルなし。ファイルへの差し替えも可能） |
| 保存 | `localStorage`（控えつき・検証つき） |
| テスト | Vitest（ゲームロジックのみ。DOM 不要） |
| フォント | DotGothic16（`@fontsource/dotgothic16`、SIL Open Font License。ビルドに同梱） |
| オフライン | 手書きの小さな Service Worker と Web App Manifest（PWA としてインストール可能） |

外部の API やサーバーは使っていません。ビルド結果は静的ファイルだけです。

## 開発サーバー

```bash
npm run dev
```

表示された URL（既定では http://localhost:5173 ）を開きます。

### 開発用の仕掛け

URL に `?debug` を付けると、確認用の機能が有効になります（付けなければ何も起きません）。

- `?debug&hour=20.5` … 店内の時刻を固定する（夜の店内を昼間に確認する、など）
- コンソールの `window.__cafe`
  - `__cafe.setLevel(7)` … 常連度を指定のレベルにする
  - `__cafe.trigger('cat')` … 窓辺の出来事を起こす（id は `src/game/data.ts` の `EVENTS`）
  - `__cafe.shiftStart(30 * 60000)` … 進行中の作業の開始を30分前にずらす
  - `__cafe.setHour(7)` / `__cafe.setHour(null)` … 時刻の固定と解除

## テスト

作業時間の計算、セッションの復旧、常連度とアンロック、セーブ／ロード、書き出し／読み込み、日付またぎ、壊れた保存データ、長時間放置、別タブとの競合、ゲームバランスを確かめています。

## ゲームの仕組み

### 作業時間の計測

タイマーの値を足していくのではなく、**開始時刻を保存して、現在時刻との差**で経過時間を求めています（`src/game/session.ts`）。
そのため、別タブに移っても、リロードしても、ブラウザを閉じて開き直しても、時間はずれません。

- 進行中の作業は開始した瞬間に保存され、開き直すと自動で復元されます
- ページが15分以上止まっていた（PC のスリープ、タブの凍結、閉じていた）ときは、「ずっと作業していた／止まった時刻までにする／記録しない」を本人に選んでもらいます。勝手に長い作業として記録することはありません
- 1回の作業は最長12時間。超えたら自動でお会計になります
- 1分に満たない作業は記録しません
- 終了ボタンを押し間違えても、レシートの「やっぱり、もう少し続ける」で戻せます（10分以内）
- 端末の時計が巻き戻っても、経過時間が負になったり記録が壊れたりしないようにしています

### 常連度

作業すると「なじみ」が貯まり、その累計で常連度（全15段階）が決まります。

- 作業1分 = なじみ 1
- その日はじめての来店（5分以上の作業）に +20
- 1日のうち6時間を超えた分は半分（累計作業時間そのものは減りません）

短い作業を毎日続ける人が不利にならず、タイマーを回し続けても得にならないようにするための設計です。
目安として、1日2時間・週5日の使い方で、最初の変化は初回の25分、紅茶は3日目、プリンは2か月ほど、最後の変化は7か月ほどで届きます。

### セーブデータ

`localStorage` に JSON で保存しています（履歴は1件100バイトほど。毎日使って数年ぶんでも数百KBに収まるので、IndexedDB は使っていません）。

| キー | 内容 |
| --- | --- |
| `cafe-time:save` | 本体 |
| `cafe-time:save:backup` | 控え（10分以上あけて、書き込む前の正常な本体を回す。読み込み・やり直しの直前にも取る） |
| `cafe-time:save:corrupt` | 読めなかった本体の退避（手作業で救うため） |
| `cafe-time:rev` | 最後に書き込んだ時刻（別タブのほうが新しいかどうかの確認用） |

- 読み込むときは必ず `sanitizeSave`（`src/game/save.ts`）を通します。壊れた項目は既定値に、壊れた履歴の行は読み飛ばし、遊べる状態にして返します
- 本体が壊れていたら控えから復元します
- 複数のタブで開いていても、古いタブが新しい記録を巻き戻さないようにしています
- 設定画面の「書き出す」で JSON ファイルとして保存でき、「読み込む」で復元できます（進行中の作業は引き継ぎません）
- 履歴は直近3000件まで保持します。累計作業時間・なじみは別に持っているので、古い履歴が消えても進行には影響しません
- データの形を変えるときは `SAVE_VERSION` を上げ、`sanitizeSave` に古い形からの読み替えを足してください

## 編集する場所

| 変えたいもの | 場所 |
| --- | --- |
| メニュー（名前・ひとこと） | `src/game/data.ts` の `MENU` |
| 常連度の名前・必要ななじみ・アンロック内容 | `src/game/data.ts` の `RANKS` |
| 作業時間の上限、来店ボーナス、1日の上限など | `src/game/data.ts` の先頭の定数 |
| 窓辺の出来事（条件・頻度・文言） | `src/game/data.ts` の `EVENTS` と `EVENT_*` 定数 |
| 天気の決まり方 | `src/game/ambience.ts` の `weatherAt` |
| 時間帯ごとの空と店内の色 | `src/scene/sky.ts` の `KEYS` |
| 店内の絵 | `src/scene/renderer.ts` |
| ドット絵のスプライト | `src/scene/sprites.ts` |
| 文言・画面 | `src/ui/` と `src/App.tsx` |

既存の `id`（メニュー、店内の変化、出来事）はセーブデータが参照しているので、変えないでください。追加は自由です。

### メニューを増やす

1. `MENU` に項目を足す
2. `src/scene/sprites.ts` に `menu.<id>` のスプライトを足す
3. `RANKS` のどこかに `unlock: { type: 'menu', id: '<id>' }` を置く

### 店内の変化を増やす

1. `DecorId` に id を足し、`RANKS` に `unlock: { type: 'decor', id }` を置く
2. `src/scene/renderer.ts` で `env.decor.has('<id>')` のときに描く

### 天候を増やす

`src/game/ambience.ts` の `WeatherKind` に種類を足し、`weatherAt` で返すようにします。
見た目は `src/scene/sky.ts` と `renderer.ts` の `drawOutside`、音は `src/audio/engine.ts` にチャンネルを足します。
外部の天気 API は使っていません（日付から決まるので、同じ日・同じ時刻なら同じ天気になります）。

## 素材の配置場所

### 画像

既定では画像ファイルを使っていません。店内もメニューも、すべてコードで描いたドット絵です。

画像に差し替えるときは `public/sprites/` に PNG を置き、`src/scene/overrides.ts` の `SPRITE_OVERRIDES` に書きます。

```ts
export const SPRITE_OVERRIDES = {
  'menu.blend': '/sprites/menu-blend.png',
};
```

画像の1ピクセルが店内の1ドットになります（目安は 24×20 ドット前後）。差し替えられる id は `src/scene/sprites.ts` の `SPRITES` を見てください。
背景（壁・窓・カウンター）は `renderer.ts` の `draw*` 関数ごとに分かれているので、1枚絵に替える場合は該当の関数を `drawImage` に置き換えます。

アプリのアイコンは `npm run icons`（`scripts/gen-icons.mjs`）で `public/icons/` に作り直せます。

### 音源

既定では音源ファイルを使っていません。BGM・店内の音・雨音は Web Audio API で合成しています。

ファイルに差し替えるときは `public/audio/` に置き、`src/audio/sources.ts` に書きます。

```ts
export const AUDIO_SOURCES = {
  bgm: ['/audio/bgm-1.mp3', '/audio/bgm-2.mp3'], // 順番に繰り返し再生
  cafe: '/audio/cafe.mp3',                         // ループ
  rain: '/audio/rain.mp3',                         // ループ
};
```

書いた系統だけがファイル再生になり、残りは合成のままです。音量とON/OFFの扱いは変わりません。
ブラウザの自動再生の制限に合わせて、音はユーザーが画面を操作したあとにだけ鳴りはじめます。

## Vercel へのデプロイ

GitHub リポジトリに push し、Vercel でそのリポジトリを連携すればそのまま公開できます。設定は `vercel.json` に入っています。

- Framework Preset: Vite（`vercel.json` で指定済み）
- Build Command: `npm run build` / Output Directory: `dist`
- 環境変数・秘密情報は不要です
- どの URL に直接アクセスしても `index.html` を返します（リロードしても壊れません）

注意点:

- **セーブデータはオリジン（ドメイン）ごと**です。本番のドメインを変えると、前のドメインの記録は見えなくなります。プレビュー用 URL も別のオリジンなので、記録は別になります。ドメインを移すときは、設定の「書き出す」→ 新しいドメインで「読み込む」で引き継げます
- `sw.js` は `no-cache` で配信しています。配信するファイルの構成を大きく変えたときは、`public/sw.js` の `CACHE` の名前（`cafe-time-v1`）を上げると古いキャッシュが消えます
- サブディレクトリで公開する場合は、`vite.config.ts` に `base` を設定し、`index.html`・`manifest.webmanifest`・`sw.js`・`src/main.tsx` にある `/` はじまりのパスも合わせてください（Vercel の既定のルート公開なら不要です）
